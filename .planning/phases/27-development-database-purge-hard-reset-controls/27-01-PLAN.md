## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client Admin UI → Backend API (`DELETE /api/v1/admin/dev-purge`) | Untrusted network requests crossing into the destructive purge route |
| Purge Engine → MongoDB User Collection | Administrative action potentially touching user credentials and accounts |
| Socket.IO Broadcaster → Client Sessions | Real-time event propagation resetting UI state across active user dashboards |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-27-01 | Elevation of Privilege | `DELETE /api/v1/admin/dev-purge` | critical | mitigate | Route is strictly protected by `authenticate` and `authorize(ROLES.ADMIN)`. Non-admin callers (DRIVER, FLEET_MANAGER, unauthenticated) are immediately rejected with 401/403 prior to executing any database logic. |
| T-27-02 | Denial of Service / Repudiation | `devPurge` Controller | high | mitigate | Require explicit confirmation payload `{ confirmPurge: true }` in request body. Requests without explicit truthy confirmation are rejected with 400 Bad Request. UI enforces a 2-step modal with 3-second countdown lock to eliminate accidental execution. |
| T-27-03 | Tampering / Information Loss | `devPurgeService.purgeAllOperationalData` | high | mitigate | User deletion query is strictly scoped to `User.deleteMany({ role: ROLES.DRIVER })`. Admin accounts (`ROLES.ADMIN`) and active sessions are explicitly preserved to prevent developer lockout. |
| T-27-SC | Tampering | npm dependencies | high | mitigate | Package-legitimacy gate: no new external packages installed; use existing verified dependencies (`express`, `mongoose`, `socket.io`, `sonner`, `lucide-react`). |
</threat_model>
