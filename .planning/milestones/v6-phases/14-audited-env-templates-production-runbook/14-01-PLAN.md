<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repo template -> Operator `.env` | Committed `.env.example` files serve as copy-paste sources for production operators; unsafe defaults copied verbatim into production cause weak JWT signing or predictable admin passwords |
| Client build args (`VITE_*`) -> Public bundle | Vite embeds `VITE_*` values into static JS assets; server-only secrets (`JWT_SECRET`, `GEOAPIFY_SERVER_API_KEY`, `SMTP_PASS`) must stay out of `client/.env.example` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-01 | Information Disclosure / Elevation of Privilege | `.env.example`, `server/.env.example` | high | mitigate | Replace all `DISALLOWED_JWT_SECRETS` literals with distinct `replace_with_random_32plus_char_*` placeholders and keep `ADMIN_PASSWORD` empty so `validateProductionEnv()` and `validateBootstrapConfig()` force unique operator-chosen credentials |
| T-14-02 | Information Disclosure | `client/.env.example` | medium | mitigate | Scope `client/.env.example` strictly to public `VITE_*` variables (`VITE_API_URL`, `VITE_SOCKET_URL`, `VITE_MAP_PROVIDER`, `VITE_GEOAPIFY_TILE_API_KEY`, `VITE_GOOGLE_CLIENT_ID`) |
| T-14-SC | Tampering | npm/pip/cargo installs | low | accept | Plan 14-01 modifies `.env.example` templates only; no package installations performed |
</threat_model>
