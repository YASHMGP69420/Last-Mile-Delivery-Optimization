# Plan 24-01: Socket Debounce, Silent Background Hydration & Lifecycle Listener Deduplication

## Objective
Eliminate unprompted multi-reloading, card flashing, and redundant API/socket request storms across driver handheld views (`DriverCockpitPage`, `DriverRoutePage`, `DriverDeliveriesPage`).

<tasks>

<task type="auto">
  <name>Task 1: Debounce triggerRefresh & Deduplicate Window Listeners in DriverSocketContext.tsx</name>
  <files>
    client/src/context/DriverSocketContext.tsx
    client/src/context/__tests__/DriverSocketContextDebounce.test.tsx
  </files>
  <action>
    1. In `DriverSocketContext.tsx`, add a `refreshTimerRef = useRef<NodeJS.Timeout | null>(null)` to manage debounce timers.
    2. Update `triggerRefresh` to debounce `setRefreshKey((prev) => prev + 1)` with a 300ms window, collapsing bursts of socket events (`delivery:updated`, `delivery:status_changed`, `route:updated`, `driver:stop_progressed`, `route:progress`) into a single atomic refresh trigger.
    3. Ensure component cleanup clears any active timer in `useEffect` unmount.
    4. Remove the redundant manual `visibilitychange` and `window.focus` listener block (lines 470–490) since `useRealtimeCatchup(refreshIdentityAndTelemetry, { debounceMs: 500 })` on line 173 already provides centralized, debounced lifecycle catchup.
    5. Create `client/src/context/__tests__/DriverSocketContextDebounce.test.tsx` verifying that calling `triggerRefresh()` 5 times within 100ms results in exactly one `refreshKey` increment after 300ms.
  </action>
  <verify>
    <automated>npm --prefix client run test:unit -- src/context/__tests__/DriverSocketContextDebounce.test.tsx</automated>
    <fails_when>Test fails, debounce timer does not collapse rapid calls, or TypeScript compilation errors exist.</fails_when>
  </verify>
  <done>
    `triggerRefresh()` collapses multiple rapid invocations within 300ms into a single `refreshKey` increment, and manual window lifecycle event duplicates are eliminated.
  </done>
</task>

  <name>Task 2: Implement Silent Background Hydration & Deduplicate Mount Effect in DriverCockpitPage.tsx</name>
  <files>
    client/src/pages/driver/DriverCockpitPage.tsx
    client/src/pages/driver/__tests__/DriverSilentHydration.test.tsx
  </files>
  <action>
    1. In `DriverCockpitPage.tsx`, update `refreshAll(silent = false)`: Only call `setIsLoading(true)` on true initial cold start when `!dashboardData && !routeData`. When data is already populated, refetches run silently in the background without resetting `isLoading`.
    2. In `refreshAll`, preserve `dashboardData` and `routeData` during refetch and only update state with new data on completion.
    3. Remove the duplicate initial mount effect `useEffect(() => { refreshAll(); }, [refreshAll]);` (lines 76–78), relying on the single mount / `refreshKey` effect (`useEffect(() => { refreshAll(); }, [refreshKey, refreshAll]);`) to eliminate double-firing on initial load.
    4. Update `useRealtimeCatchup(refreshAll, { debounceMs: 400 })` to pass `silent = true` to prevent screen wakes from flashing the UI cards.
    5. Create `client/src/pages/driver/__tests__/DriverSilentHydration.test.tsx` asserting that when data is present, invoking background refresh does not toggle `isLoading` to true.
  </action>

    <fails_when>Non-zero exit code or background refresh toggles isLoading to true when state is populated.</fails_when>
  </verify>
  <done>
    `DriverCockpitPage` loads once cleanly on mount; subsequent background refetches update metrics, vehicle status, and stop state without resetting `isLoading` or re-animating GSAP cards.
  </done>
